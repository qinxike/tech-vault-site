一、 BRD、MRD、PRD 与 MVP 的核心区别

前三者是产品规划阶段的**三份递进文档**，而最后一个是产品落地的**交付策略与实物形态**。

| 比较维度     | BRD（商业需求文档）                 | MRD（市场需求文档）                   | PRD（产品需求文档）                 | MVP（最小可行性产品）                    |
| -------- | --------------------------- | ----------------------------- | --------------------------- | ------------------------------- |
| **本质属性** | **文档**（商业战略层）               | **文档**（市场战术层）                 | **文档**（产品执行层）               | **产品实物 / 策略**（市场验证层）            |
| **核心问题** | **值不值得做？**  <br>（商业价值与投资回报） | **做成什么样能赢？**  <br>（市场机会与竞争策略） | **具体怎么做？**  <br>（功能逻辑与交互细节） | **最快做出什么能验证市场？**  <br>（用最低成本试错） |
| **核心内容** | 商业背景、盈利模式、成本预算、收益预测、风险评估    | 市场规模、用户画像、竞品分析、核心功能规划         | 信息架构、业务流程、交互原型、字段规则、异常处理    | 砍掉非核心功能，仅保留能跑通核心业务的最简闭环         |
| **产出形态** | 商业简报（通常为 PPT）               | 调研分析报告（Word / PPT）            | 详细说明书 + 原型图（Figma / Axure）  | **可实际运行的产品**（如极简版小程序、Web 或 App） |
| **主要受众** | 公司高层、老板、投资人                 | 项目组、市场/运营团队、产品团队              | 研发（前后端）、测试、UI/UE 设计师        | **真实种子用户**（用于测试市场反应与收集数据）       |

- **四者协作关系**：**BRD** 负责立项拿预算，**MRD** 负责找准市场切入点；产品经理运用 **MVP 思维**砍掉冗余功能，将其转化为第一版 **PRD**；最终研发团队依据 PRD 做出 **MVP** 推向市场验证。

---

MRD,PRD核心区别一览表

| 比较维度     | MRD（市场需求文档）                  | PRD（产品需求文档）                        |
| -------- | ---------------------------- | ---------------------------------- |
| **关注核心** | 解决“**为什么做**”和“**市场要什么**”     | 解决“**做什么**”和“**具体怎么实现**”           |
| **主要内容** | 目标市场分析、用户群体、竞品分析、核心需求概述、商业价值 | 功能模块结构、详细业务逻辑、页面交互流程、异常处理、接口及非功能需求 |
| **阅读对象** | 项目组、产品团队、市场与运营人员、高层决策者       | 研发（前端、后端）、测试、UI/UE 设计师、项目经理        |
| **输出形式** | 偏向于市场调研报告、策略分析               | 偏向于产品蓝图、详细设计说明书                    |
| **先后顺序** | **先写**（承上启下，由 BRD 延伸而来）      | **后写**（基于 MRD 转化落地）                |
|          |                              |                                    |

--- 

详细解析

- **MRD（市场需求文档）—— “从市场到产品方向”**
    - **作用**：它是连接商业战略（BRD）与具体产品功能的桥梁。回答的问题是：_市场上存在什么机会？我们的目标用户是谁？竞争对手在做什么？我们该切入什么功能点来满足市场？_
    - **典型内容**：
        - 目标市场与行业背景分析
        - 用户画像与核心痛点分析
        - 竞品优劣势分析（SWOT分析等）
        - 产品功能需求概况与优先级划分

- **PRD（产品需求文档）—— “从构思到落地执行”**
    - **作用**：它是产品开发的“施工图纸”。回答的问题是：_这个功能具体长什么样？用户点击这里会发生什么？系统在后台怎么处理？_
    - **典型内容**：
        - 产品信息架构与功能结构图
        - 详细的业务流程图（Swimlane / Flowchart）
        - 页面交互逻辑与原型图（Axure/Figma等）
        - 字段规则、状态说明、异常提示及技术/非功能需求

> **关系总结**：可以把它们比喻为盖房子——**BRD** 决定“要不要盖这栋楼（商业可行性）”，**MRD** 决定“盖什么类型的楼、建在哪个地段、比旁边竞争对手的楼好在哪里（市场定位）”，而 **PRD** 则是具体的“建筑设计图纸与施工规范（工程实现）”。
